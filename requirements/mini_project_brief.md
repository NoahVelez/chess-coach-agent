Presented in Class 7 (Oct 12). This is your first agent, built by you, alone. It is deliberately low-stakes and hands-on: the point is to build a working agent yourself before you propose a bigger one with a team.

What to build

One small agent that solves a real, specific pain point from your own work, studies, or life.
It must actually run and do something useful end to end — a working tool, not a sketch.
Hand-rolled is encouraged (you will have seen exactly how in Classes 5 and 6). A framework is allowed, but you must understand what it does.
Use synthetic or your own non-sensitive data. Never use confidential or personal data.
What to submit

Your agent, committed to your course GitHub repository.
A short README section describing the problem it solves and how to run it.
A brief in-class presentation (5 minutes plus Q&A): the problem, how you built the agent, and what it does.
How it is graded

See the Mini-Project rubric below. In short: a working agent, evidence that you understand how it works, and a clear explanation.
| Criterion | What good looks like |
|---|---|
| **Working agent** | Runs end to end and does something genuinely useful — not a stub or a demo that only half-works. |
| **Understanding** | You can explain how it works and why you built it that way; you are not just relaying tool output. |
| **Explanation** | The presentation clearly conveys the problem, the build, and the result in the time given. |
| **Real problem** | Solves an actual pain point, not a contrived toy task. |
